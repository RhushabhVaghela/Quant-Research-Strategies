## 1. Frozen economic question

The predictive gate has passed. The next question is not whether we can find a better signal; it is whether the **already-frozen protected-validation signal** can be translated into executable economics under a concrete, pre-registered portfolio and cost model.

The economic test uses only the protected-validation observations generated by the frozen 003H candidate:

- next 5-minute cross-sectional excess return;
- same 15 eligible equities;
- additive OLS on `close_location_1bar + intraday_position_60bar`;
- training-only standardization;
- protected validation: 2026-06-10 through 2026-08-19;
- final holdout beginning 2026-08-20 remains untouched.

## 2. Frozen portfolio

At every eligible protected-validation timestamp:

- rank the 15 equities by the frozen prediction;
- long Q5 = 3 stocks;
- short Q1 = 3 stocks;
- equal notional within each side;
- 50% gross notional long and 50% gross notional short;
- net exposure 0%;
- hold one 5-minute bar;
- rebalance on every eligible signal timestamp;
- close any remaining positions after the final signal timestamp;
- no leverage, thresholds, symbol filters, time-of-day filters, volatility scaling, or holding-period search;
- no overnight positions.

The validated target is close(t) to close(t+1), so the implementation is a **close-to-close execution proxy**, not an assertion that a real order receives the recorded close.

## 3. Portfolio notional and return accounting

Brokerage is charged per executed order, so the test must use **real rupee notional**, not normalized unit weights.

Default reported size: **₹1,00,000 gross portfolio notional**.

The portfolio notional is a capital-scale input; it does not change rankings, weights, holding period, or signal selection. The runner may be repeated at other pre-declared sizes for sensitivity, but a size must not be chosen after observing results to manufacture a favorable cost outcome.

The economic record must distinguish four different quantities:

- the **per-bar portfolio return**, produced by the fixed 50% long / 50% short portfolio;
- the **cumulative gross portfolio return**, calculated by compounding the sequence of one-bar returns;
- **cumulative executed turnover**, measured in rupees and as a multiple of the initial gross portfolio notional;
- **costs and net cumulative P&L**, calculated from actual executed turnover and the selected portfolio notional.

Cumulative turnover can legitimately exceed the starting portfolio notional by hundreds of times over a 711-bar sample because the same capital is repeatedly deployed. That is an execution-intensity measure, not evidence that more than the starting capital was held simultaneously.

## 4. Turnover

For each signal timestamp, target weights are +1/6 for each of three Q5 longs and −1/6 for each of three Q1 shorts. The runner calculates executed turnover from **changes in target weights** between adjacent signal timestamps:

```
sum(abs(current_weight_i - previous_weight_i)) × portfolio_notional
```

and then explicitly closes the final portfolio.

This is the correct way to avoid pretending that every timestamp necessarily creates six fresh buys plus six fresh sells. A persistent position can generate zero or partial turnover at the next rebalance.

The reported turnover multiple is:

```
cumulative executed turnover / initial gross portfolio notional
```

It is therefore expected to be greater than 1× in a sequential intraday strategy.


## 5. Fee model

Use the current published Zerodha NSE equity intraday schedule:

- brokerage: ₹20 or 0.03%, whichever is lower, per executed order;
- STT: 0.025% on sell turnover;
- NSE transaction charge: 0.00307% on buy + sell turnover;
- stamp duty: 0.003% on buy turnover;
- SEBI turnover fee: ₹10/crore;
- GST: 18% on brokerage + transaction charges + SEBI charges.

## 12. Implementation audit and invalidation — 24 September 2026

The first local execution of the economic runner completed 711 portfolio timestamps but produced **1,060.333× cumulative turnover on a ₹1,00,000 portfolio notional** and ₹53,091.53 of fee charges. Those outputs are **invalid for the economic decision gate** because the accounting implementation was not yet acceptable.

Two accounting issues were identified:

1. cumulative gross return had been reported as a simple sum of one-bar returns rather than as a geometric sequence of one-bar portfolio returns;
2. the turnover/cost result requires explicit treatment of repeated one-bar portfolio capital and order-level charges, with the ₹20 brokerage cap applied to actual rupee order notionals.

The execution runner has been corrected and the superseded output must not be used as evidence.

The corrected runner:
- compounds the one-bar portfolio returns for cumulative gross return;
- reports cumulative executed turnover separately from portfolio notional;
- computes brokerage per executed order with the ₹20 cap;
- applies statutory charges to actual executed turnover;
- applies the frozen execution-friction assumptions to actual executed turnover;
- retains the late-session / potential CAS diagnostics;
- continues to reject any protected input on or after 2026-08-20.

**No economic pass/fail decision is recorded from the superseded run. A clean rerun of the corrected implementation is required.**
